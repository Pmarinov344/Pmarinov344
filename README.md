## 📌 Featured Project — Product Ownership in Practice

### 🎓 [Virtual Teacher](https://github.com/FinalProjectTeam06/VirtualTeacher)

An eLearning platform where teachers publish courses and video lectures, and students enroll, submit assignments, and get graded — with an admin panel, ratings, and a Wikipedia lookup feature via the MediaWiki Action API.

**My role went beyond development.** As Team Lead, I owned the product definition end-to-end: I authored the full technical/product documentation (SRS) — system goals and scope, functional and non-functional requirements, a prioritized backlog of user stories with acceptance criteria and story-point estimates — then led the team through the SDLC, running planning and refinement, managing the backlog, and translating stakeholder needs into development-ready specs.

<summary>📄 &nbsp;<b>View product documentation — scope, requirements & user stories</b></summary>

<br>

**System goal:** a virtual educational platform where students register and learn from teachers who create courses and deliver video lectures, with admins handling verification, certificates, and platform-wide control.

**Core scope:**
- Registration & user profiles for students and teachers
- Course & lecture management (title, topic, description, embedded video, assignments)
- Student area — enrolled courses, personal notes, assignment submissions
- Grading & ratings — teacher feedback on submissions, course ratings after completion
- Teacher admin section — manage courses, comments, and search students (post-approval)
- Admin dashboard — full control over users, courses, and teacher/admin approvals
- Optional extras — enrollment confirmations, notification emails, certificates, social login, Wikipedia search integration

**Functional requirements (excerpt):**

| # | Requirement | Priority |
|:-:|---|:-:|
| 1 | User registration & profile management for students and teachers | 🔴 High |
| 2 | Course & lecture creation, editing, and deletion | 🔴 High |
| 3 | Student dashboard — enrolled courses, submissions, notes | 🟡 Medium |
| 4 | Assignment submission, teacher grading & feedback, course ratings | 🔴 High |
| 5 | External integration with the MediaWiki Action API (Wikipedia search) | 🔴 High |
| 6 | Enrollment confirmations, notification emails, certificates | 🟡 Medium |

**Non-functional requirements:**

| Category | Requirement | Priority |
|---|---|:-:|
| Security | Passwords ≥ 8 characters with uppercase, digit & special character; unique, verified emails | 🔴 High |
| Usability | Search, filter, and sort courses in the catalog | 🟡 Medium |
| Compatibility | Integration with external services (MediaWiki Action API) | 🟡 Medium |
| Legal | GDPR-compliant handling of personal data | 🟢 Low |

**Sample user stories (backlog excerpt):**

| ID | As a... | I want to... | So that... | Points |
|:-:|---|---|---|:-:|
| 1 | user | register an account | I can create and manage a personal profile | 5 |
| 2 | user | log in to the system | I get access to personalized functionality | 3 |
| 4 | user | download a certificate after completing a course | I have proof of successful completion | 3 |
| 6 | user | search courses in the catalog | I can find courses relevant to me | 3 |
| 7 | user | submit an assignment for a lecture | the teacher can grade it and I get feedback | 5 |

*Full SRS (including system architecture, module decomposition, and the conceptual database model) is included in the project's `/docs` folder.*
